# User Story R00027: Timer stoppen

## Wer, wie, warum

**Wer:** Ein Mensch, der mit der Arbeit an einer Karte fertig ist und die gemessene Zeit festhalten will — und ein KI-Agent, der dasselbe über die API tut. Dazu ein Dritter, den es bisher nicht gab: **irgendjemand**, der am nächsten Morgen sieht, dass ein fremder Timer über Nacht weitergelaufen ist, und ihn beendet.

**Wie:** Auf der Kartenseite steht im Abschnitt „Zeiten" statt der stillen Zeile „läuft seit 08:04" ein Knopf **„Stoppen"**. Ein Klick — und dort steht wieder **„Timer starten"**, die Plakette auf der Karte in der Bahn ist fort, und wer später weiterarbeitet, startet einfach neu. Ein Agent tut dasselbe mit `PUT /api/karten/14/zeiten/7/ende` **ohne Rumpf** und liest den fertigen Eintrag über `GET /api/karten/14` zurück: `beginn`, `ende`, Kontributor.

**Warum:** Die Vision verlangt „einen Timer, den man startet **und stoppt**, ohne Umstand". Gestartet werden kann seit `R00026` — beendet noch nicht, und deshalb trägt bis heute **kein einziger Eintrag ein Ende**. Ohne Ende gibt es keine Dauer, ohne Dauer keine Summe, keinen Soll-Ist-Vergleich, keinen Burndown und nichts zu exportieren. Dieser Slice erzeugt den ersten vollständigen Zeiteintrag.

**Jeder darf stoppen, auch einen fremden Timer.** Die Anwendung läuft im LAN ohne Anmeldung — das ist eine Leitplanke der Vision, keine Lücke. Und ein Agenten-Timer, der über Nacht weiterläuft, muss von jemandem beendet werden können, sonst wächst eine Messung ins Unendliche. Der Eintrag behält dabei den Kontributor, für den er läuft: **gestoppt wird der Timer, nicht die Urheberschaft.** Deshalb bekommt der Aufruf auch keinen Kontributor mit — es gäbe nichts, was die Anwendung damit täte.

**Ein zweiter Stopp verschiebt das Ende nicht.** Er ist kein Fehler — das Ziel des Aufrufs ist erreicht, und ein Agent, dessen Antwort unterwegs verlorenging, soll den Aufruf gefahrlos wiederholen können. Aber anders als beim zweiten *Start* stünde hier etwas auf dem Spiel: beim Start verliert niemand etwas, beim Stopp verlöre man **gemessene Zeit**, wenn der zweite Aufruf das Ende nach hinten schöbe. Das Ende bleibt deshalb stehen, wo es steht.

**Der Vorbehalt gehört dazugesagt:** dass ein zweiter Stopp einfach durchgeht statt eine Meldung zu bekommen, ist heute richtig, weil es gegen ein gesetztes Ende **nichts zu tun** gäbe — Korrigieren gibt es noch nicht. Sobald es das gibt (`I0025`), ist die Frage neu zu stellen.

**Eine Messung von null Sekunden ist erlaubt; eine negative nie.** Wer startet und sofort wieder stoppt, hat eine sehr kurze Zeit gemessen — das ist eine wahre Aussage, keine Fehleingabe. Springt dagegen die Uhr des Servers zurück, wird das Ende auf den Beginn geklemmt: eine negative Dauer vergiftete jede spätere Summe. **Diese Klemmung ist eine stille Korrektur** — die Anwendung schreibt 0:00 und sagt es niemandem, weil der Aufrufer gegen die Serveruhr ohnehin nichts ausrichten könnte. Die Skizze zeigt eine Zurückweisung „Das Ende liegt vor dem Beginn" — die gehört zum **Nachtragen von Hand** (`I0025`), wo der Mensch beide Zeitpunkte selbst eingibt und sie auch korrigieren kann.

**In der Oberfläche kann man hier weniger als über die API — mit Absicht.** Beendbar ist im Browser nur der **eigene** Timer, weil das Stoppquadrat am fremden Eintrag an einer Zeile hängt, die es noch nicht gibt: die Einträgeliste gehört `I0026`. Über die API geht der fremde Stopp heute schon. Das bricht die Regel „was die Oberfläche kann, kann die API" nicht — sie ist eine Zusage in **eine** Richtung. Das gezeichnete Bild wird damit erst mit `I0026` vollständig.

**Nach dem Stopp kann man wieder starten.** Auf derselben Karte, für denselben Kontributor. Das ist keine neue Funktion, sondern die Folge davon, dass „läuft" genau „kein Ende" heißt — aber es wird geprüft, weil sich sonst niemand darauf verlassen kann.

**Nicht dabei:** keine Zeitensumme, keine Einträgeliste, kein Nachtragen oder Ändern von Hand, kein Stoppen fremder Timer im Browser, keine Kopfzeilen-Übersicht, keine Live-Nachführung, keine gerenderte Dauer im Knopf, kein „Soll" neben dem Ist, keine Schemaänderung.

## Szenarien

### US-1: Ich stoppe meinen Timer auf der Karte

**Als** Mensch, der mit dieser Karte für jetzt fertig ist,
**will ich** die Zeitmessung mit einem Klick beenden,
**damit** die Zeit festgehalten ist und nicht einfach weiterläuft.

- **Gegeben** ich habe in diesem Tab die Identität „Stefan" gewählt
- **Und** auf der Karte `WBS-14` läuft für mich seit 08:04 ein Timer
- **Wenn** ich die Kartenseite `/karten/14` öffne
- **Dann** steht im Abschnitt „Zeiten" ein Knopf **„Stoppen"** mit der Angabe, seit wann er läuft
- **Und** dort steht **kein** Startknopf
- **Wenn** ich „Stoppen" drücke
- **Dann** steht an derselben Stelle wieder **„Timer starten"**
- **Und** es gibt dort keinen Stoppknopf mehr
- **Und** es erscheint **keine** Summenzeile und **keine** Eintragsliste — die gehören einem späteren Schritt

### US-2: Die Plakette auf der Karte in der Bahn verschwindet

**Als** Mensch, der auf das Board schaut,
**will ich** sofort sehen, dass auf dieser Karte nichts mehr läuft,
**damit** ich mich nicht auf eine Anzeige verlasse, die von gestern ist.

- **Gegeben** ich habe wie in US-1 den Timer auf `WBS-14` gestoppt
- **Wenn** ich zurück auf das Board gehe
- **Dann** trägt `WBS-14` **keine** Plakette mehr
- **Wenn** ich die Seite neu lade
- **Dann** trägt sie weiterhin keine
- **Und** die Kartenseite zeigt weiterhin „Timer starten"

### US-3: Der Agent stoppt über die API und liest den fertigen Eintrag zurück

**Als** KI-Agent, der seine Arbeitszeit erfasst,
**will ich** die Messung über die API beenden und den vollständigen Eintrag abrufen können,
**damit** meine Zeit genauso zählt wie die eines Menschen — ohne Bildschirm.

- **Gegeben** auf Karte 14 läuft für den Kontributor 3 der Zeiteintrag 7 seit 08:04
- **Wenn** ich `PUT /api/karten/14/zeiten/7/ende` **ohne Rumpf** aufrufe
- **Dann** antwortet die API mit **200**
- **Und** die Antwort ist ein Zeiteintrag mit `zeiteintragId` 7, `karte` 14, dem Kontributor 3 als **ganzem Kontributor** und dem **unveränderten** `beginn` 08:04
- **Und** `ende` ist **nicht null**
- **Wenn** ich danach `GET /api/karten/14` aufrufe
- **Dann** trägt die Antwort denselben Eintrag mit `beginn`, `ende` und Kontributor
- **Wenn** ich `GET /api/boards/1` aufrufe
- **Dann** steht dieser Eintrag **nicht** mehr in der Liste der laufenden Zeiteinträge
- **Und** läuft sonst keiner, ist die Liste **leer** — nicht `null` und kein Fehler
- **Wenn** die WebApi neu startet
- **Dann** steht derselbe beendete Eintrag noch da

### US-4: Ein fremder Timer lässt sich beenden

**Als** Mensch, der morgens sieht, dass der Timer eines Agenten über Nacht weitergelaufen ist,
**will ich** ihn beenden können,
**damit** aus einer vergessenen Messung keine zwölfstündige Arbeitszeit wird.

- **Gegeben** auf Karte 14 läuft der Timer des Kontributors 3 („Claude", Art `Agent`)
- **Und** ich bin nicht dieser Kontributor
- **Wenn** ich `PUT /api/karten/14/zeiten/7/ende` aufrufe
- **Dann** antwortet die API mit **200** — der Aufruf wird **nicht** zurückgewiesen
- **Und** der Eintrag trägt weiterhin den Kontributor **3**: gestoppt wurde der Timer, nicht die Urheberschaft
- **Und** der Aufruf hat **keinen** Kontributor genannt — weder im Rumpf noch in der Adresse
- **Gegeben** der Kontributor 5 ist **stillgelegt** und hat noch einen laufenden Timer
- **Wenn** ich diesen Timer beende
- **Dann** antwortet die API mit **200**
- **Und** es kommt **keine** Meldung „Kontributor stillgelegt" — starten darf er nicht mehr, sein laufender Timer muss trotzdem enden können
- **Wenn** ich dasselbe in der Oberfläche versuche
- **Dann** gibt es dort für einen **fremden** Timer noch keine Handlung — das gehört zur Einträgeliste eines späteren Schritts

### US-5: Der zweite Stopp verschiebt das Ende nicht

**Als** KI-Agent, dessen Antwort unterwegs verlorenging,
**will ich** den Stoppaufruf gefahrlos wiederholen können,
**damit** ich nicht raten muss, ob er angekommen ist — und keine Zeit dazuerfinde.

- **Gegeben** der Zeiteintrag 7 lief seit 08:04 und wurde um 09:40 beendet
- **Wenn** ich `PUT /api/karten/14/zeiten/7/ende` um 11:15 ein zweites Mal aufrufe
- **Dann** antwortet die API mit **200** — nicht mit einem Fehler
- **Und** `ende` ist **09:40**, nicht 11:15
- **Und** die gemessene Dauer bleibt **1:36** und wächst nicht auf 3:11
- **Wenn** ich danach `GET /api/karten/14` aufrufe
- **Dann** ist die Zeiteinträge-Liste um **keinen** Eintrag gewachsen
- **Und** der Eintrag trägt dieselben Werte wie nach dem ersten Stopp

### US-6: Eine Messung von null Sekunden ist erlaubt, eine negative nie

**Als** jemand, der später eine Zeitsumme liest,
**will ich** mich darauf verlassen, dass keine Dauer negativ ist,
**damit** eine einzige verkorkste Messung nicht die ganze Auswertung verfälscht.

- **Gegeben** ich starte einen Timer und stoppe ihn im **selben** Zeitpunkt
- **Wenn** der Stopp durchläuft
- **Dann** antwortet die API mit **200**
- **Und** `ende` ist gleich `beginn`
- **Und** die Dauer ist **0:00** — der Aufruf wird nicht zurückgewiesen
- **Gegeben** ein Timer läuft seit 08:04:00
- **Und** die Uhr des Servers ist inzwischen auf 08:03:30 zurückgesprungen
- **Wenn** ich stoppe
- **Dann** ist `ende` **08:04:00** und nicht 08:03:30
- **Und** die Dauer ist 0:00 und nicht minus 30 Sekunden
- **Und** es erscheint **keine** Meldung — die Korrektur geschieht still, weil ich gegen die Serveruhr nichts tun könnte
- **Und** es gibt in diesem Schritt **keine** Zurückweisung „Das Ende liegt vor dem Beginn" — die gehört zum Nachtragen von Hand

### US-7: Nach dem Stopp kann ich wieder starten

**Als** Mensch, der nach der Mittagspause an derselben Karte weiterarbeitet,
**will ich** den Timer erneut starten können,
**damit** ich zwei Abschnitte messe statt einen langen mit Pause darin.

- **Gegeben** ich habe meinen Timer auf `WBS-14` gestoppt
- **Wenn** ich auf der Kartenseite wieder „Timer starten" drücke
- **Dann** läuft ein **neuer** Timer
- **Und** er hat eine **andere** Nummer als der beendete
- **Und** der beendete Eintrag bleibt daneben stehen
- **Wenn** ich `GET /api/karten/14` aufrufe
- **Dann** trägt die Karte **zwei** Einträge: einen mit Ende und einen ohne
- **Und** der Aufruf ist **nicht** an einer Eindeutigkeitsregel gescheitert — sie gilt nur für **offene** Einträge

### US-8: Fehler sagen, was zu tun ist

**Als** KI-Agent, der ohne Bildschirm arbeitet,
**will ich** bei jedem abgelehnten Aufruf den Grund mit Werten und die nächste Aktion bekommen,
**damit** ich mich selbst korrigieren kann, statt zu raten.

- **Gegeben** die API der Anwendung
- **Wenn** ich einen Timer an einer Karte stoppe, die es **nicht gibt**
- **Dann** antwortet sie mit **404** und `karte-unbekannt`
- **Und** der Grund nennt die Kartennummer, die ich geschickt habe
- **Und** die Kompensation sagt, wo ich gültige Karten finde
- **Wenn** ich eine Zeiteintragsnummer schicke, die es an **dieser** Karte nicht gibt
- **Dann** antwortet sie mit **404** und einem eigenen Code für den unbekannten Zeiteintrag
- **Und** der Grund nennt **beide** Nummern — die der Karte und die des Zeiteintrags
- **Und** die Kompensation verweist auf `GET /api/karten/{karteId}`, wo die gültigen Nummern stehen
- **Wenn** es die Karte gar nicht gibt und die Zeiteintragsnummer erst recht nicht
- **Dann** antwortet sie über die **Karte** und nicht über den Zeiteintrag — sonst schickte sie mich auf eine Adresse, die selbst 404 antwortet
- **Wenn** ich einen Zeiteintrag stoppe, den es zwar gibt, der aber an einer **anderen** Karte liegt
- **Dann** wird er wie ein unbekannter behandelt
- **Wenn** ein Aufruf zurückgewiesen wurde
- **Dann** hat sich an **keinem** Zeiteintrag etwas geändert

### US-9: Fällt die WebApi aus, sagt es die Oberfläche

**Als** Mensch vor der Kartenseite,
**will ich** eine lesbare Meldung statt einer Ausnahmeseite,
**damit** ich weiß, dass mein Stopp nicht angekommen ist.

- **Gegeben** die Kartenseite mit meinem laufenden Timer ist geöffnet
- **Und** die WebApi ist nicht erreichbar
- **Wenn** ich „Stoppen" drücke
- **Dann** erscheint eine lesbare Ausfallmeldung
- **Und** die Seite bleibt bedienbar
- **Und** der Knopf zeigt weiterhin „Stoppen" — der Timer läuft ja noch
